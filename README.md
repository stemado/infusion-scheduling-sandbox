# Infusion scheduling sandbox

An interactive, entirely fictional learning model about appointment duration restrictions, staff coverage, room suitability and unused capacity. All people, schedules and rules are illustrative; the page does not describe a particular clinic or software product.

Open index.html in a browser. It is self-contained and needs no installation or server.

## Pages

- [Scheduling scenarios](index.html): explore unused reserved time, nurse coverage and room requirements.
- [Why lanes?](why-lanes.html): compare fixed and flexible assignments, then test how known nurse availability changes whether a request can fit. Introduces feasibility, optimization, and false positives and negatives.

## Publish with GitHub Pages

1. Create a dedicated repository in the intended personal account, for example infusion-scheduling-sandbox. A public repository supports Pages on GitHub Free.
2. Upload index.html, why-lanes.html, .nojekyll and this README.md to the repository root on main.
3. In Settings > Pages, choose Deploy from a branch, select main and /(root), then Save.
4. When deployment completes, open the Visit site link shown in Pages settings.

The project URL follows https://USERNAME.github.io/REPOSITORY/. The website is public and associated with the owning GitHub account.

[GitHub Pages setup documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## Scope

There is no patient-data input, analytics, external runtime dependency or clinical-system connection. The explanation links to public references for its terminology. Copy buttons write fictional discussion questions to the clipboard. Results are teaching examples, not clinical or operational recommendations.
